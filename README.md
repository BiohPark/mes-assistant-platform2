# MES Agent Hub (데모)

사내 AI 에이전트(OpenWebUI 모델)를 **카드 카탈로그**로 고르고, 에이전트와의 **대화 1개 = 업무 1개**로 일합니다.
대화끼리는 **태그(SR 번호·키워드)** 로 느슨하게 연결되고, 같은 태그를 가진 대화의 산출물은 **공유 자료함**에서 발견해 **사람이 고른 것만** AI 입력으로 씁니다.
백엔드 없이 브라우저 IndexedDB에 저장하고, LLM은 Mock 응답 또는 사내 OpenAI-compatible endpoint를 직접 호출하는 **프론트 전용 데모**입니다.

설계: [docs/conversation-hub.md](docs/conversation-hub.md) (현행) · [docs/design.md](docs/design.md) (이전 패키지 모델) · 계획: [docs/superpowers](docs/superpowers)

## 실행

```bash
npm install
npm run dev        # http://localhost:5174
npm run build      # dist/ 정적 파일 (사내 웹서버 어디든 배포 가능)
npm run preview    # 빌드 결과 미리보기
npx vitest run     # 도메인/DB/LLM 단위 테스트
```

첫 실행 시 시드(사용자 6명, 에이전트 12개 — 가상 카탈로그, 대화 11건, SR 6건)가 자동 주입됩니다.
이전 버전(패키지 모델) 데이터는 DB 업그레이드 시 자동 변환되고, 예전 백업(JSON v1)도 가져올 때 변환됩니다.

> SPA 라우팅을 쓰므로 정적 서버에서는 모든 경로를 `index.html`로 fallback 해야 합니다 (nginx `try_files $uri /index.html;`).

## 주요 화면

| 경로 | 화면 |
|---|---|
| `/` | 상단 토글 **[에이전트 카드 \| 전체 대화 칸반]**. 카드 클릭 → 바로 대화. System Owner는 **편집 모드**(드래그로 공통 순서, 클릭으로 설정) |
| `/?view=kanban` | **전체 대화 칸반** — 열 = 에이전트(카드와 같은 순서), 카드 = 대화(최근 활동순). 단계(Lv1/Lv2)·상태 다중 필터, 내 대화, 태그 필터, 빈 열 접기, 열 미니맵. 필터는 URL에 남아 공유 가능 |
| `/new/:assistantId` | **새 대화 초안** — 입력창·"시작"·사용예시 칩. **첫 전송 때만** 대화가 만들어짐(빈 업무 없음) |
| `/c/:taskId` | **대화** — 채팅(스레드 1개), 태그 입력(자동완성), 연결된 대화, 오른쪽 [자료 · 체크 · 노트 · 히스토리]. `/tasks/:id`는 여기로 이동 |
| `/assistants/manage` | **에이전트 관리** — 순서·분류·이름·요약·**모델 ID 인라인 매핑**·링크1·링크2·담당자·상태·사용예시 |
| `/sr` · `/sr/manage` | SR 접수(접수 에이전트와 대화 → 명시적 "접수로 전환", AI 제목) · SR 관리(진행 현황, **연결 업무 시작**, 결과 공유) |
| `/reports` | 완료 추이, 에이전트별 현황, **자료 흐름(출처 → 입력 사용)**, **태그별 대화**, SR 분포, 비효율 신호(이전 버전 입력 등) |
| `/settings` | LLM 연결(Mock/Live), 공통 기본 모델, SR 접수 에이전트, 데이터 내보내기/가져오기 |

## 핵심 개념

- **대화 = 업무**. 에이전트 하나, 스레드 하나, 상태·체크리스트·노트·산출물을 가집니다.
- **태그**: SR 코드(`SR-YYYY-NNNN`, 저채도 결정색)와 자유 키워드(중립색). Obsidian처럼 Enter/쉼표로 추가, Backspace로 삭제, 사용 빈도순 자동완성. 개수 제한 없음.
- **발견과 사용의 분리**
  - 공유 자료함 = 나와 **직접** 태그를 공유하는 대화의 파일만(A–B–C 간접 확산 없음), 출처 에이전트 순으로 묶고 이전 버전은 접습니다.
  - 태그만으로는 AI에 아무것도 가지 않습니다. **☑ 참고 / ★ 주 입력**으로 고른 버전만 프롬프트에 들어가며, 주 입력이 먼저 갑니다.
  - 새 버전이 나와도 선택은 자동으로 바뀌지 않고 "새 버전 있음 · 바꾸기"만 표시합니다. 태그를 떼도 이미 고른 입력은 유지됩니다.
  - 산출물은 자동: 답변을 "산출물로 저장"하면 같은 태그 대화의 자료함에 나타납니다.
- **제목**: 기본 제목으로 시작 → 첫 답변 뒤 별도 요청으로 AI 제목(Mock/실패 시 첫 메시지 규칙). 사람이 고친 제목은 다시 덮어쓰지 않습니다. SR 제목도 같은 원칙(요청자·SO만 수정).
- **SR**: 기본 접수 에이전트는 **URS 분석 도우미**. SR 상세의 **연결 업무 시작**은 에이전트를 고르면 SR 태그가 붙은 새 대화를 만들고, 같은 SR로 진행 중인 대화가 있으면 **이어가기**를 먼저 제안합니다.
- **모델**: 이 대화 지정 › 에이전트 매핑(`modelId`) › 공통 기본 모델. 링크에서 모델을 추정하지 않으며, 링크1은 저장값이 없을 때만 `{OpenWebUI}/?model={모델 ID}`로 만듭니다.
- **안전장치**: 주입 자료 앞 프롬프트 인젝션 가드, 다른 대화가 입력으로 쓰는 파일·대화 삭제 차단, 접수 에이전트 폐기/삭제 방지, 필수 체크 누락 완료·재개 사유 기록, 팀 의견(AI 미전송), 응답별 "전송 기록".

## 데모 스토리

1. 홈 카드 **FDS 작성 도우미** 클릭 → "시작" 전송 → 질문 흐름. 뒤로 가기만 하면 대화가 생기지 않음
2. `WK-2026-0002` 열기 → 자료 탭: 주 입력 URS v1에 **새 버전 있음** → 필요할 때만 "바꾸기"
3. `WK-2026-0004`(테스트 시나리오) → 공유 자료함에서 FDS ☑, URS ★ → 전송 → "전송 기록"에서 주 입력이 먼저 들어간 것 확인
4. 태그 칩 클릭 → 해당 태그로 필터된 칸반. `release-2026-10`만 가진 CCA 대화에서는 CC 초안이 보이지 않음(간접 확산 없음)
5. `/sr` 새 대화 → "접수로 전환"(AI 제목) → `/sr/manage`에서 **연결 업무 시작** → SR 태그가 붙은 대화
6. System Owner로 **편집 모드** → 카드 드래그 → 순서 저장 → 칸반 열도 같은 순서
7. `/assistants/manage`에서 모델 ID 매핑 → 대화 헤더의 모델 표시가 "에이전트 매핑"으로 바뀜

## 우리 회사에 맞게 설정하기

시드의 에이전트·사람·SR은 모두 **가상 예시**입니다. 실제로 쓸 때는 아래만 바꾸면 됩니다.

1. **설정 → LLM 연결**: Live 모드, 사내 OpenWebUI API 주소(`http://…/api`)와 키, 공통 기본 모델을 지정합니다.
2. **관리(`/assistants/manage`)**: 에이전트를 사내 OpenWebUI 모델에 맞게 등록·수정합니다.
   - 모델 ID: OpenWebUI의 모델 ID. 비우면 공통 기본 모델을 씁니다.
   - 링크1: OpenWebUI에서 해당 에이전트를 여는 주소. 비우면 `{OpenWebUI 주소}/?model={모델 ID}`로 만들어집니다.
   - 업무 Lv1/Lv2: 칸반의 단계 필터가 이 값으로 만들어집니다(예: Record › Deviation, SDLC › 설계).
   - 주로 쓰는 입력 / 주요 산출물: 대화 화면 자료 패널의 안내로 표시됩니다(강제 아님).
3. **홈 → 편집 모드**(System Owner): 카드 순서 = 칸반 열 순서를 정합니다.
4. **설정 → SR 접수 에이전트**: 요청자와 대화할 에이전트를 고릅니다.
5. 처음부터 비어 있는 상태로 시작하려면 `src/db/seed/*`의 목록을 줄이거나 설정에서 데이터를 가져오기(JSON)로 교체합니다.

## LLM 연결

- 설정 → Live 모드, 프리셋(OpenWebUI `http://…/api`, vLLM `/v1`, Ollama) 선택 후 API 키 입력, "연결 테스트".
- 브라우저에서 직접 `{baseUrl}/chat/completions`(SSE)와 `{baseUrl}/models`를 호출하므로 서버 CORS 허용이 필요합니다.
- 입력 파일은 텍스트(≤12,000자)만 system prompt에 인라인됩니다. 실서비스에서는 OpenWebUI Files API를 권장합니다.

## 한계 (데모)

브라우저 저장(용량·공유 불가), API 키 브라우저 보관, 인증 없음(사용자 전환은 시연용), 크로스 PC 실시간 없음(같은 브라우저 탭끼리만 공유).
